# PAIR Naming and Terminology Guide

Version: **PAIR Framework v0.2.0**

This guide defines the public naming convention for the `physical-ai-readiness` repository and related research, tools, reports, and deployments.

## Core Names

### Repository

`physical-ai-readiness`

Use this exact repository name when referring to the GitHub project.

### Framework

**PAIR — Physical AI Readiness**

PAIR is the conceptual and methodological framework. It organizes readiness across four domains:

- **P — Place**
- **A — Architecture**
- **I — Institutions**
- **R — Returns**

### Public Beta Tool

**PAIR Assessment Tool**

This is the current software implementation of the framework.

Preferred subtitle:

**Physical AI Readiness**

Recommended browser title:

`PAIR Assessment Tool | Physical AI Readiness`

### Current Assessment Output

**PAIR Readiness Profile**

Use this term for the current output across the ten readiness dimensions and four PAIR domains.

The beta may also report a **Preliminary Overall Maturity** value as contextual information.

Do not call this value a PAIR Index score.

### Future Validated Product

**PAIR Index**

Reserve this name for a future version supported by repeated application, methodological refinement, evidence validation, weighting analysis, and comparative benchmarking.

Do not describe the current beta as a validated index.

## Domain Language

Use the following domain names and questions consistently.

### P — Place

**Question:** Is the physical environment ready?

Dimensions:

1. Physical Infrastructure
2. Curb, Access & Public Realm
3. Energy, Charging & Depot Capacity

### A — Architecture

**Question:** Can Physical AI connect to the wider system?

Dimensions:

4. Digital & Data Infrastructure
5. Mobility & System Integration

### I — Institutions

**Question:** Can we govern, operate, and respond?

Dimensions:

6. Governance & Institutional Capacity
7. Workforce & Operations
8. Safety, Emergency Response & Resilience

### R — Returns

**Question:** Does deployment create value?

Dimensions:

9. Public Trust, Equity & Community Acceptance
10. Economic Development & Deployment Viability

## Methodological Language

Preferred sequence:

**PAIR Domain → Readiness Dimension → Evidence → Maturity Assessment → Gap → Action → Deployment → Evaluation**

Preferred maturity levels:

1. Not Ready
2. Emerging
3. Pilot-Ready
4. Deployment-Ready
5. Adaptive & Scalable

Preferred early-stage description:

> PAIR is an exploratory research and decision-support framework for evaluating the readiness of places and institutions for Physical AI deployment.

Preferred disclaimer:

> PAIR is currently an exploratory research and decision-support framework. The PAIR Assessment Tool is not a certification system, regulatory standard, safety assessment, or validated comparative index.

## Terms to Avoid in v0.x

Avoid the following unless clearly describing future work:

- validated PAIR Index
- official readiness score
- certification
- safety certification
- regulatory compliance score
- definitive city ranking
- scientifically validated composite index

## Versioning

Methodology and software should be versioned separately when practical.

Example:

- **PAIR Framework v0.2.0** — methodology
- **PAIR Assessment Tool v0.2.0** — application release

A software interface change does not necessarily imply a methodology change. A change to dimensions, scoring, maturity thresholds, weights, or evidence standards should trigger a framework-version review.
